# Money module behind MoneyTracker / OS Money

MoneyTracker orchestrated many service imports (`loadAllData` Promise.all), so balance invariants and expense side effects lacked locality. **Decision:** deepen a **Money** module with a small interface — `getOverview({ month })`, `recordExpense`, `analyzeStatement`, `importStatement`, `setBucketTargets`, `setBufferGoal`. `getOverview` returns monthly **Income**, **Spent**, **Planned**, and **Saved** for the selected calendar month (`YYYY-MM`), merging ledger transactions with imported statement rows and excluding own-account (including **Savings ↔ Spending**) transfers from Income/Spent. It also returns **Needs / Wants / Future** actuals vs editable target percentages (default Future/savings **10%** of Income, Needs 50 / Wants 40), **Buffer** progress from the **Savings** balance, **Runway**, and a month-start **Transfer suggestion** (plan total − Spending balance; Savings-after-transfer; Buffer warning; plan Runway). Plan total = in-month planned expenses + annual costs / 12 + monthly budget lines. `importStatement` parses via existing bank adapters (ING / ABN / Rabo CSV shapes), skips duplicate rows, marks own-account transfers, and persists through the statement Store adapter. The OS Money page and the legacy tracker are thin clients. Existing `*Service` / statement parsers remain adapters. Money tables keep RLS with no anon policies. ADR-0004 keeps Money in primary nav — deepen in place, do not drop from nav. No parallel Money domain API on the Agent Service; Day Plan / Analytics hooks stay thin readers of this module.
